# Project working agreements

## Visual review standard

For every user-visible UI change, screenshot review is part of the definition of done:

1. Capture the implemented interface after tests pass, using the real local or deployed build rather than a mock.
2. Include at least one desktop screenshot and one phone-size screenshot.
3. Include any important interaction state changed by the work, such as placement, an open panel, or a completed flow.
4. Save the screenshots under `docs/screenshots/` and embed them in the final response so feedback can be given directly.
5. Mention what each screenshot is intended to validate and keep temporary viewport overrides from affecting later browser work.
